## Defects found and fixed

### Joined editor could not set a project tag

The newly joined Klee member saw an incomplete Chat type without the linked `Tag` property even though the space exposed the global multi-select property. Project selection failed with `This Chat type has no writable Tag property`.

Knot now falls back to the space-level `tag` multi-select property when the chat object and type omit that relationship. The live retry selected `imai`, and the next Codex task opened in the configured `imai` workspace.

### Raw Codex tool identifiers leaked into progress

ACP tool titles could contain shell commands, absolute paths, UUIDs, execution IDs, guard-assessment IDs, and MCP method names. Knot now maps those values to bounded labels such as `Running a command`, `Searching Anytype`, `Reading files`, and `Reviewing changes`.

### Existing Anya DM was not attached

The OpenClaw identity's Anytype API did not include its one-to-one space in `listSpaces`, although Heart's `ensure-dm` returned the existing space and chat. Knot previously waited for discovery and therefore never created the route.

Knot now verifies that the returned space contains exactly the configured agent and authorized peer, caches that membership, and attaches the returned route immediately. The deployed build passed the Anya DM retry without creating another identity or direct-message chat.
